# RAG 3.0 PRD文档套装 — 设计说明

**创建日期**: 2026-06-05
**设计来源**: docs/5-企业级RAG知识库3.0实现方案.md
**状态**: 已确认

## 产出物清单

| # | 文档文件名 | 定位 | 核心内容 |
|---|-----------|------|----------|
| 1 | `BRD-业务需求文档.md` | 决策层 | 市场背景、业务痛点（"六个不等于"）、商业价值、ROI、竞品对比、实施路线图 |
| 2 | `PRD-产品需求文档.md` | 产品/开发 | 用户画像、用户故事(Epic→Story)、功能规格(5层架构逐层)、非功能需求(四高四低) |
| 3 | `技术架构设计.md` | 架构师/开发 | 系统架构图、5大流水线设计、4分类器路由、融合层、安全合规、技术选型 |
| 4 | `数据库设计.md` | 后端/DBA | ER图、MySQL表结构、向量库Schema、ES索引Mapping |
| 5 | `API接口设计.md` | 前后端 | RESTful API规范(OpenAPI 3.0)，知识库/文档/查询/对话/权限/评测 |

## 设计原则

- 中文为主，技术术语保留英文原名
- 用户故事: `作为<角色>，我希望能<目标>，以便<价值>`
- 架构图使用 Mermaid
- API 使用 OpenAPI 3.0
- 数据库 DDL 基于 MySQL 8.0+

## 命名约定

| 术语 | 含义 |
|------|------|
| RAG 3.0 | 产品代号，多路召回→多层融合→自适应路由 |
| 知识源 | 用户上传的原始文档/URL/数据库连接 |
| 知识库 | 解析→分块→嵌入→索引后的可检索集合 |
| 流水线 | 独立检索通道：向量/PageIndex/GraphRAG/Wiki/工具调用 |
| 融合层 | 多条流水线结果融合排序的中间层 |
| Agentic Router | 入口智能路由，由4个分类器驱动 |
