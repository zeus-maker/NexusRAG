# 测试用例设计：企业级RAG 3.0知识库系统

> 版本：v1.0
> 日期：2026-06-06
> 系统架构：分类器路由 + 多通道异构检索 + 持久化知识编译 + 混合融合
> 技术栈：Python 3.11+, pytest, Locust, RAGAS, DeepEval

---

## 1. 测试策略总览

### 1.1 测试金字塔

| 层级 | 占比 | 目标 | 工具 |
|------|------|------|------|
| 单元测试 | 70% | 各模块独立逻辑正确性 | pytest, pytest-mock |
| 集成测试 | 20% | 模块间交互、API端到端 | pytest, httpx, testcontainers |
| E2E测试 | 10% | 用户关键路径验证 | pytest, Playwright |

**金字塔原则**：
- 单元测试覆盖所有核心算法与业务逻辑，执行速度快（< 5分钟全量）
- 集成测试验证模块间契约与数据流，使用真实中间件的容器化实例
- E2E测试聚焦5-8条关键用户旅程，模拟真实用户操作

### 1.2 测试分类

| 分类 | 目标 | 工具 | 频率 |
|------|------|------|------|
| 功能测试 | 验证功能正确性 | pytest | 每次提交 |
| 性能测试 | 验证性能SLO | Locust | 每周 + 版本发布前 |
| 安全测试 | 验证安全合规 | OWASP ZAP, 自研脚本 | 每月 + 版本发布前 |
| 评测测试 | 验证RAG生成质量 | RAGAS, DeepEval | 每日构建 + 模型变更时 |
| 兼容性测试 | 验证多环境适配 | pytest, Docker matrix | 每周 |

### 1.3 测试环境

| 环境 | 用途 | 配置 | 数据 |
|------|------|------|------|
| 开发环境（Docker Compose） | 日常开发调试 | 本地Docker, 8C16G | 合成测试数据 |
| CI环境（GitHub Actions） | 自动化测试 | GitHub Runner, 4C8G | 标准测试集 |
| 预发布环境（K8s Staging） | 发布前验证 | K8s集群, 16C32G | 脱敏生产数据 |
| 性能测试环境（独立集群） | 性能基准测试 | 独立K8s, 32C128G | 生产级数据量 |

**环境隔离要求**：
- 各环境独立数据库与中间件，互不干扰
- 性能测试环境独占资源，避免干扰
- 预发布环境与生产环境配置一致

## 8. 测试自动化

### 8.1 CI/CD集成

#### 8.1.1 GitHub Actions工作流配置

```yaml
# .github/workflows/test.yml
name: Test Pipeline

on:
  pull_request:
    branches: [main, develop]
  schedule:
    - cron: '0 2 * * *'    # 每日02:00
    - cron: '0 4 * * 0'    # 每周日04:00

jobs:
  unit-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Set up Python 3.11
        uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      - name: Install dependencies
        run: pip install -e ".[dev]"
      - name: Run unit tests
        run: pytest tests/unit/ -v --cov=src --cov-report=xml
      - name: Upload coverage
        uses: codecov/codecov-action@v4

  integration-test:
    runs-on: ubuntu-latest
    needs: unit-test
    services:
      mysql:
        image: mysql:8.0
        env:
          MYSQL_ROOT_PASSWORD: test
      elasticsearch:
        image: elasticsearch:8.12.0
      milvus:
        image: milvusdb/milvus:v2.3.4
      redis:
        image: redis:7.2
    steps:
      - uses: actions/checkout@v4
      - name: Run integration tests
        run: pytest tests/integration/ -v

  e2e-test:
    runs-on: ubuntu-latest
    needs: integration-test
    if: github.event_name == 'schedule'
    steps:
      - uses: actions/checkout@v4
      - name: Run E2E tests
        run: pytest tests/e2e/ -v

  rag-eval:
    runs-on: ubuntu-latest
    needs: integration-test
    if: github.event_name == 'schedule'
    steps:
      - uses: actions/checkout@v4
      - name: Run RAGAS evaluation
        run: python -m ragas evaluate --dataset tests/eval/finance_bench_v1.json

  performance-test:
    runs-on: ubuntu-latest
    if: github.event_name == 'schedule' && github.event.schedule == '0 4 * * 0'
    steps:
      - uses: actions/checkout@v4
      - name: Run Locust performance tests
        run: locust -f tests/perf/locustfile.py --headless -u 100 -r 10 -t 5m
```
