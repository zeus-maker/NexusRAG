## 第 6 页｜第二章 RAG核心原理：索引+检索+生成

- **数学本质**：从P(Y|X) → P(Y|X, D)，参数化+非参数化混合记忆
- **索引阶段**：原始文档 → 解析清洗 → 智能分块 → Embedding → 向量/关键词索引
- **索引关键**：保留版面结构 / 平衡语义完整性 / 选择合适的Embedding模型 / 元数据标签 / 增量更新
- **检索阶段**：Query改写 → 向量+BM25双路 → RRF融合 → Cross-Encoder重排 → 权限过滤 → 上下文压缩
- **生成阶段**：Prompt组装 → LLM推理 → 带引用答案 → 输出验证 → 最终回答
- **核心约束**：强制基于上下文 / 降级策略（诚实说不知道）/ 引用溯源

## 第 7 页｜第二章 RAG vs 其他范式

- **RAG vs 关键词搜索**：语义理解 vs 精确匹配，答案可溯源 vs 需人工筛选
- **RAG vs 微调**：文档级更新vs需重训，成本低vs高，解决知识vs风格
- **RAG vs Long-Context LLM**：成本可控vs API费用高，知识容量不限vs受窗口限制
- **核心优势**：可解释性 / 实时更新 / 数据可控 / 成本可控 / 可量化评估
- **核心局限**：依赖检索质量 / 上下文窗口限制 / 多跳推理弱 / 工程复杂度高
- **警示**：简单RAG一周可搭建，生产级需跨越7+个工程决策点

## 第 11 页｜第四章 双模态PDF-RAG与表格处理（下）

- **双模态架构核心**：类型检测 → 长篇论文用Docling / PPT课件用PyMuPDF
- **父子分块策略**：Child Chunk(200-400 token)做向量检索，Parent Chunk(1000-2000 token)做LLM上下文
- **小基准数据（3篇论文/18页/8个query）**：朴素文本Top-1 25% → Markdown 50% → 元素JSON 62.5%
- **表格处理原则**：HTML>Markdown / 存摘要+原文 / 向量化存摘要，检索时调取原表
- **扫描件避坑**：DPI<150需precision模式 / 混合语言设置ch_en / 手写体用olmOCR
- **解析质量指标**：字符完整率>95% / 表格保留率>90% / 阅读顺序>95% / OCR准确率>97%
- **核心建议**：POC阶段即投入解析质量优化，回报率远超后续调整

## 第 12 页｜第五章 分块策略：七大方法详解（上）

- **分块三要素**：大小200-500字 / 重叠10-20% / 依据：语义>段落>字符
- **① 固定大小分块**：简单可预测，但切断语义 → 仅MVP验证
- **② 递归字符分块（LangChain默认）**：优先保持段落完整 → 通用文本首选
- **③ 文档结构分块**：按Markdown标题/代码AST切分 → 技术文档/API手册
- **④ 语义分块**：基于Embedding相似度变化 → 对话内容/复杂合同
- **⑤ 句子窗口**：检索用单句，生成用窗口上下文 → FAQ/问答对
- **⑥ 父子索引**：检索匹配Child(细)，生成用Parent(全) → 论文/合同/技术规范
- **⑦ 命题分块**：LLM提取独立事实 → 高质量QA/知识图谱

## 第 13 页｜第五章 分块策略：基准数据与决策（下）

- **NVIDIA 2025基准**：页面级分块最优（准确率0.648/标准差0.107最稳定）
- **粒度与查询类型**：Factoid查询256-512 token / 复杂分析1024或页面级 / 数字定位256-512
- **关键发现**：自然页面边界封装一致性信息单元；分块策略ROI > Embedding模型选型
- **中文特殊处理**：全角符号适配 / 使用bert-base-chinese Tokenizer / 专有名词保护 / 段落合并
- **常见坑**：一刀切参数 / 块太小缺上下文 / 块太大有噪声 / 缺重叠 / 表格被切碎 / 代码被切碎
- **推荐方法论**：页面级默认起步 → 按文档类型细化 → 评估数据驱动迭代

## 第 15 页｜第六章 Embedding微调与成本优化

- **微调数据**：搜索日志1000-10000条 / 专家标注100-500条 / LLM合成5000+条
- **微调效果**：内部项目代号+87% / 医疗缩写+42% / 金融术语+32% / 通用FAQ+3.5%

## 第 16 页｜第七章 向量数据库：ANN算法原理

- **核心能力**：高效ANN检索 / 元数据过滤 / 水平扩展 / 混合检索 / 高可用
- **HNSW**：多层图结构，检索极快(对数复杂度)，召回>95% → 百万~千万级最佳选择
- **关键参数**：M=16-64（连接数）/ efConstruction=100-200 / ef=50-500
- **IVF**：聚类分cell，内存友好 → 千万~百亿级；与PQ结合压缩64倍
- **PQ量化**：1024维float32(4096字节)→64字节，牺牲3-5%召回换巨大存储节省
- **生产组合**：HNSW（快速检索）+ PQ（压缩存储）；Milvus 2.5原生BM25混合检索

## 第 18 页｜第八章 混合检索：BM25+向量的工业级实践（上）

- **纯向量检索失效边界**：精确术语查询（合同编号/产品型号/法规条款）向量召回<BM25的一半
- **BM25核心**：TF饱和 / 文档长度归一化 / IDF罕见词加权
- **稀疏vs密集**：BM25擅长精确术语/短查询/OOV词；向量擅长语义近似/长查询/跨语言
- **生产数据**：BM25关键词召回72% → 混合搜索91%（+25pp）
- **识别标准**：用户查询中精确编号/专有名词>30%必须上混合检索

## 第 19 页｜第八章 三种融合方式与生产实践（下）

- **① RRF倒排融合**（默认选择）：`1/(k+rank)`，与分数量纲无关，无需训练，所有主流向量库原生支持
- **② 凸组合**（调优方案）：`α×向量 + (1-α)×BM25`，仅需40个标注query调α，超RRF
- **α调优经验**：技术文档≈0.3 / 对话策略≈0.7-0.8 / 通用≈0.6
- **③ 学习排序LTR**（上限最高）：需标注数据，适合超大成熟系统
- **2025前沿**：按查询动态调整α，分级混合NDCG提升7.5%（朴素RRF仅1.3%）
- **生产流水线**：BM25召回50 → 向量召回50 → 动态α融合 → MMR去重 → Cross-Encoder重排 → Top-10
- **经验法则**：教程类纯向量够用 / 合同法规必须混合 / FAQ+复杂文档混合+动态α

## 第 20 页｜第九章 重排序：RAG的质量分水岭（上）

- **核心命题**：Embedding决定"找不找得到"，Rerank决定"用不用得上"
- **双编码器**（Bi-Encoder）：Query和Doc独立编码，快但精度有限 → 第一阶段检索
- **交叉编码器**（Cross-Encoder）：联合编码+完整注意力，精确但慢 → 第二阶段重排
- **核心数据**：Reranker普遍提升Hit Rate 5-10pp；混合+BGE-Rerank-base Hit Rate@3达93%
- **bge-reranker-v2-m3**：多语言/8K长文本/性价比首选 / 开源Apache 2.0
- **Cohere Rerank 3**：多语言/Nimble快/NDCG领先5-10% / 闭源付费

## 第 21 页｜第九章 推荐流水线与评估（下）

- **bge-reranker系列全景**：base(0.3B/CPU) → v2-m3(0.6B/多语言) → v2-gemma(2B/精度最高) → v2.5-gemma2-lightweight(9B/最新SOTA)
- **分层自蒸馏**：教师信号=最终排序分，学生信号=各中间层，可灵活选择输出层数
- **推荐流水线**：混合检索 → Top-100 → MMR去重 → Cross-Encoder Rerank → Top 5-10 → LLM
- **MMR位置**：必须在Rerank之前，避免对近乎重复片段做交叉编码
- **延迟控制**：30候选≈100-200ms / 200候选=5-10倍爆炸 / 候选保持在50以下
- **LLM当Reranker**：极致精度但500ms+延迟，$0.001/doc，仅高价值场景

## 第 22 页｜第十章 GraphRAG：知识图谱增强检索（上）

- **传统RAG的致命缺陷**：分块切断上下文；向量检索对结构关系和逻辑引用"盲目"
- **典型场景**：合同第3条定义术语→第17条才用到，被切成不同chunk无法关联
- **实际测试**：传统RAG关联型问题召回≈70%，GraphRAG增强→99%+
- **核心思想**：文档解析时自动抽取实体+关系→构建图谱→检索时向量+图遍历双路
- **Microsoft GraphRAG**（31K+ Stars）：实体抽取 → Leiden社区检测 → 社区摘要 → 双模式查询
- **Local vs Global**：Local=从实体出发1-2跳邻居；Global=遍历社区摘要map-reduce

## 第 23 页｜第十章 GraphRAG效果与成本（中）

- **多跳推理准确率**：Naive RAG 35% → Advanced 52% → GraphRAG **78%** → RAG 2.0 87%
- **幻觉率**：传统18% → GraphRAG 7% → RAG 2.0 4%
- **KG-LM基准**：GraphRAG 54.2% vs 纯向量 16.7% → 提升3.3倍
- **GraphRAG的成本挑战**：100万token建图消耗50-100万token LLM调用
- **LazyGraphRAG突破**：索引成本降低99.9%至向量RAG同等水平；查询成本降低700倍+
- **核心思路**：不在索引阶段预处理，查询时按需迭代提取概念及共现关系

## 第 24 页｜第十章 GraphRAG实践决策（下）

- **适用场景**：法律合规 / 医药研发 / 金融研报 / 复杂工程图纸 → 实体关系明确
- **不适用**：客服对话(实体稀疏) / 社交媒体(短文本) / 通用博客(主题分散)
- **LightRAG**：双层检索(实体级+主题级) / 增量更新 / 与现有向量库无缝集成
- **Agentic-GraphRAG**：成本再降90%，按需提取+Agent剪枝+国产模型适配
- **落地效果**：LinkedIn MRR+77.6% / NVIDIA金融忠实度96% / Lettria准确率50%→80%+
- **经验法则**：先跑2-3个月普通Hybrid RAG积累日志，再有针对性建子图

## 第 25 页｜第十一章 Agentic RAG：从被动检索到自主推理（上）

- **传统RAG局限**："一次性检索"不能分解复杂问题 / 不能调整策略 / 不能多轮深入
- **核心思想**："规划-执行-反思"循环，Agent自主决策检索策略
- **六大能力跃迁**：单次→多轮迭代 / 固定策略→动态决策 / 无工具→API+SQL+图谱 / 无失败处理→自动重试
- **核心工具集**：search_documents(多模式) / search_graph(图遍历) / query_database(SQL) / search_web(外部) / calculate(计算)
- **工具设计原则**：明确描述→LLM据此决策 / 参数化模式选择 / 返回结构化结果

---

## 第 26 页｜第十一章 Agentic RAG的挑战与实践（下）

- **90%生产失败率**：检索质量本就差 → Agent放大问题 / 状态管理困难 / Token爆炸 / 错误传播 / 评估困难
- **反面教训**：Agent建立在弱检索之上，复杂度更高反而放大问题
- **LangGraph方案**（事实标准）：状态机驱动 / retrieve→grade→generate→critique循环 / Critic提升准确率78%→93%
- **AgenticRAG四工具**（2025论文）：search/find/open/summarize，single-shot→agentic 5.9×改进
- **渐进式策略**：①普通RAG → ②Query改写+混合 → ③单Agent+检索 → ④Router Agent → ⑤多Agent
- **核心原则**：可靠性90%+再增复杂度；高风险决策必须人工确认

## 第 27 页｜第十二章 多模态RAG：文本→全模态跃迁（上）

- **必然性**：企业知识70%+为非文本 / 客服40%+查询涉图表 / 纯文本RAG丢失近一半价值
- **多模态架构**：模态识别→分路处理(文本/图像/表格/音频)→统一向量存储(带模态标签)→混合检索→多模态生成
- **图像处理方案**：VLM(GPT-4o)生成描述 → CLIP做Embedding → 统一向量检索
- **最佳实践**：Ensemble策略——MinerU提取版面+高分辨率图片，olmOCR增强复杂区域
- **VLM vs Pipeline**：olmOCR(VLM端到端/强于LaTeX/上手写体) vs MinerU(Pipeline/坐标信息/学术论文)
- **成本控制**：GPT-4o图像为纯文本10-20倍；跳过<200×200小图；批量并发≤5/秒

## 第 28 页｜第十二章 表格与多模态最佳实践（下）

- **表格三大原则**：HTML>Markdown（保留合并单元格）/ 存摘要+原文（向量存摘要，检索调原表）/ 表格独立成块
- **表格感知检索**：检测表格关键词→仅检索table类chunk→不与其他文本混排
- **多模态生成**：text_results排序+image_results(最多3张) → Vision LLM统一回答
- **2026推荐技术栈**：PDF提取PyMuPDF+GPT-4o / 表格Pandas+摘要 / 图像CLIP+BGE-m3 / 视频Twelve Labs / 音频Whisper-v3
- **关键洞察**：多模态核心不在技术而在内容质量；图像描述准确性+表格分块策略决定最终效果
- **生产策略**：CLIP做检索、VLM做精排的两阶段策略，平衡效果与成本

## 第 29 页｜第十三章 Prompt工程：成本最低效果最大的优化

- **核心地位**：精心设计的Prompt可将准确率从60%提升到85%
- **五大组件**：角色设定（严谨的XX专家）/ 核心指令（基于上下文禁止编造）/ 降级策略 / 引用要求 / 输出格式
- **关键技巧1**：用强硬否定词"禁止/绝不允许"，不用"请不要"
- **关键技巧2**：Few-shot 2-3个精简示例（信息覆盖/不足/多来源三种情况）
- **关键技巧3**：上下文排序（最相关在前）+ 引用格式强制（[来源:文档名,页码]）
- **反模式**：无角色/无约束/无降级/无引用/过长的Few-shot/中英混杂/模糊指令
- **A/B测试**：建立Prompt版本管理，100条测试集驱动迭代

## 第 30 页｜第十四章 安全合规：五层防御体系（上）

- **五层防御**：接入层(WAF+限流+SSL) → 认证层(SSO+JWT+MFA) → 授权层(RBAC+ABAC+文档级) → 数据层(加密+脱敏+审计) → 模型层(Prompt过滤+输出审查)
- **合规六标准**：等保2.0(政务) / GDPR(欧盟) / ISO 27001(国际) / SOC 2(SaaS) / 个保法(中国) / HIPAA(医疗)
- **文档级权限**：部门+角色+用户+时间有效期四维控制；向量检索先权限过滤再检索
- **数据脱敏**：Presidio检测PII(人名/身份证/电话) → AES-256字段加密 → 全链路脱敏
- **多租户隔离**：租户解析必须在检索前；共享基础设施可，共享检索面不可；缓存按租户隔离

## 第 32 页｜第十五章 RAG评估：RAGAS四大指标（上）

- **评估挑战**：检索≠生成；端到端指标掩盖组件问题；需要多维度协同评估
- **RAGAS四大核心**：Context Precision(检索信噪比) / Context Recall(检索覆盖度) / Faithfulness(答案忠实度) / Answer Relevancy(答案相关性)
- **Faithfulness计算**：答案→拆解为claims→每个claim能否从contexts推断→忠实比例
- **Answer Relevancy**：从答案生成假设问题→计算与原问题的Embedding平均相似度
- **阈值经验**：Context Precision≥0.70 / Recall≥0.80 / Faithfulness≥0.85(红线) / Relevancy≥0.80

## 第 33 页｜第十五章 评估框架对比与策略（下）

- **RAGAS**：30+指标(含AspectCritic/MultiModal/NoiseSensitivity)，事实标准
- **DeepEval**：pytest集成，14+指标，适合CI/CD；**TruLens**：可视化根因分析
- **双轨评测体系**：全量自动化(RAGAS回归) + 10%人工抽检(覆盖边界case)
- **评估陷阱**：评估集不能代表真实查询 / 自动化指标有盲区(看不出时效性错误) / 忽略边界场景 / 一次性评估后不跟踪
- **测试集构建**：从生产日志采样而非人工构造；起步50-100条 / 标准200-500条 / LLM合成需人工校验
- **持续监控**：每日faithfulness/延迟/低质量率/高延迟率报告 → 实时告警

## 第 34 页｜第十六章 性能优化与成本控制
